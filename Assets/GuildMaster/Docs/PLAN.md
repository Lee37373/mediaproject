# 구현 계획서 (PLAN)

어느 세션에서 시작하더라도 같은 결과를 낼 수 있도록 **남은 작업을 작업 단위로 정의**한 문서입니다.

- **설계 배경**: `DESIGN.md`
- **현재 상태**: `PROGRESS.md` (작업 ID로 체크)
- **코딩 규칙과 테스트 방법**: 루트의 `CLAUDE.md`

## 사용 규칙
1. 작업은 **ID 순서대로** 진행합니다. `의존`이 모두 완료된 작업만 시작합니다.
2. 시작하기 전에 해당 작업의 **미결 질문**을 확인합니다. `❓`가 남아 있으면 사용자에게 먼저 묻습니다.
3. 작업이 끝나면 다음을 합니다.
   - 컴파일 → EditMode 테스트 → 플레이 검증
   - `PROGRESS.md` 체크
   - 사용자가 원하면 커밋
4. 계획과 다르게 구현했다면 이 문서를 먼저 고친 뒤 진행합니다. 문서와 코드가 어긋나지 않게 합니다.

### P3-1 특성(Trait) 시스템
- **의존**: 없음
- **파일**
  - `Traits/TraitDefinition.cs` (ScriptableObject)
  - `Traits/TraitSet.cs` (효과 합산, `AdjustQuestValue`, UI용 `Format`)
  - `Traits/TraitRoller.cs` (생성 규칙)
  - `Data/DefaultContent.cs` (기본 특성 추가)
  - `Data/GameDatabase.cs` (`traits` 목록)
- **TraitDefinition 필드**
  - 기본: `id, displayName, description, isPositive`
  - 스탯: `hpMul, atkMul, defAdd, speedMul, sightAdd`
  - 행동: `retreatShift, fatigueMul, expMul`
  - 퀘스트 선호: `goldGreed, dangerAversion, partyAffinity`
  - 영입: `recruitDifficulty`
  - LLM: `promptHint` (한국어 한 줄)
  - `conflicts` (상충 특성 목록)
- **기본 특성 (± 각 8개 내외)**

  | 긍정 | 효과 | 부정 | 효과 |
  |---|---|---|---|
  | 용감함 | 후퇴 -0.1, 위험 선호 | 겁많음 | 후퇴 +0.15, 위험 회피 |
  | 강골 | HP +20% | 허약함 | HP -20% |
  | 명사수 | 공격 +15% | 서투름 | 공격 -15% |
  | 근면함 | 피로 ×0.7 | 게으름 | 피로 ×1.4 |
  | 빠른 학습자 | EXP ×1.3 | 탐욕스러움 | 골드 선호 ×1.5, 영입 어려움 |
  | 날렵함 | 이속 +15% | 느림보 | 이속 -15% |
  | 매의 눈 | 시야 +2 | 외톨이 | 파티 선호 ×0.5 |
  | 사교적 | 파티 선호 ×1.4 | 오만함 | 영입 어려움 |
  | 충성스러움 | 영입 쉬움 | | |

  상충 쌍: 용감함↔겁많음, 강골↔허약함, 명사수↔서투름, 근면함↔게으름, 날렵함↔느림보, 사교적↔외톨이
- **생성 규칙**
  - 개수: 1개 40%, 2개 40%, 3개 20%
  - 긍정일 확률 55%, 상충 특성 제외
  - `AdventurerGenerator`에서 `TraitRoller`로 부여하고, `AdventurerData.traitIds`에 저장
  - 의뢰 가치 보정(구현): 골드 몫 × (goldGreed-1) 가산, × (1 - dangerAversion×0.25×위험도), 이미 맡은 사람이 있으면 × partyAffinity
- **연결 지점**
  - `AdventurerStats.Compute`(스탯 보정)
  - `Adventurer.RetreatThreshold`, 피로와 EXP 배율
  - `RuleBasedDecisionMaker.Score`(`TraitSet.AdjustQuestValue`)
  - 인스펙터와 길드원 창에 표시(긍정은 초록, 부정은 빨강)
- **완료 기준**
  - EditMode 테스트: 상충 제외, 스탯 보정
  - 길드원 창에 특성 표시

### P3-2 LLM 퀘스트 판단
- **의존**: P3-1
- **파일**
  - `Adventurers/LlmDecisionMaker.cs`
  - `Adventurers/Prompts/DecisionPrompt.cs`: 프롬프트와 DTO를 모아 둡니다. 게임 타입이 필요하므로 Gameplay 쪽에 둡니다.
- **요청 컨텍스트**: 기획서 3.2 스키마를 확장한 JSON
  ```json
  {"npc_id","name","class","level","mbti","values","traits":[promptHint...],
   "status":{"hp_percent","gold","fatigue","stress","potions"},
   "available_quests":[{"quest_id","target","reward_gold","reward_exp","danger","party_size","members"}],
   "recent_events":[GameLog 최근 5줄]}
  ```
- **응답 (GBNF 강제)**
  - `{"action":"accept_quest|rest|shop|idle", "quest_id":<실제 가능한 ID 또는 "">, "reason":str≤80, "say":str≤60}`
  - `quest_id`는 요청할 때마다 문법을 새로 만들어 **실제 ID만 허용**합니다.
- **검증과 대체 경로**
  - 다음 경우에는 `RuleBasedDecisionMaker.Decide`로 대체합니다: 파싱 실패, ID 불일치, HP 30% 미만인데 수락(안전 규칙), 게이트웨이가 `Ok=false`.
  - 요청 설정: `DedupeKey = npc_id`, 우선순위 `Decision`, 타임아웃 25초
- **표시**
  - 결정의 `say`를 말풍선으로 띄우고, `reason`은 인스펙터의 "최근 생각" 줄에 보여 줍니다.
- **등록**
  - `GameBootstrap`에서 `IAdventurerDecisionMaker`를 LLM 구현체로 교체합니다. LLM 구현체 안에서 규칙 기반 판단을 대체 경로로 씁니다.
- **완료 기준**
  - LLM이 켜진 상태에서 모험가 결정의 70% 이상이 `FromLLM`
  - LLM을 끄면(`LlmGateway.Enabled=false`) 규칙 기반으로 정상 루프
  - 성격과 특성에 따라 다른 선택을 하는지 로그로 확인

### P3-3 방문자와 영입 대화
- **의존**: P3-1
- **파일**
  - `Recruitment/VisitorService.cs`
  - `Recruitment/RecruitmentSession.cs`
  - `Recruitment/RecruitPrompt.cs`
  - `UI/Views/RecruitDialogView.cs`
  - `Adventurers/VisitorStates.cs`
- **방문**
  - 12~20 게임시간마다 방문자가 옵니다(길드가 정원 초과면 생략). 레벨은 `1 + 경과일/4`에 무작위 편차를 더합니다.
  - 방문자는 무작위 성문에서 등장해 광장에 12시간 머뭅니다(`VisitorWanderState`). 그 뒤 성문으로 떠나고 사라집니다.
  - 방문자는 `IsGuildMember=false`, `Faction.Visitor`입니다. 몬스터에게 공격받지 않고 퀘스트도 받지 않습니다.
- **상호작용**
  - 인스펙터에서 방문자를 선택하면 "영입 대화" 버튼이 나옵니다.
  - 아바타가 3칸 이내로 다가간 뒤 대화창이 열립니다.
- **대화창**
  - 프로필: 직업, 레벨, 특성(±색), MBTI, 가치관
  - 대화 기록, 입력칸, 보내기 버튼
  - 계약금 입력(Q5)과 [정식 영입 제안] 버튼, 호감도 막대, "생각 중…" 표시
- **LLM**
  - 시스템 프롬프트: 방문자 페르소나(이름, 성격, 특성 힌트, 기대 계약금 = `레벨×30×탐욕도`)와 길드 정보(길드원 수, 골드, 건물 레벨, 최근 사건)
  - 대화 기록은 직접 관리합니다(최근 6턴을 프롬프트에 포함, `addToHistory=false`).
  - 응답: `{"reply":str≤100, "affinity_delta":-15~15, "decision":"undecided|join|refuse"}`
- **판정 규칙**
  - 호감도는 40에서 시작하고, 특성의 `recruitDifficulty`와 가치관 일치 여부로 보정합니다.
  - `join`이면서 호감 50 이상, 또는 호감 85 이상이면 영입됩니다.
  - `refuse`이면서 호감 35 미만이면 떠납니다.
  - 6턴이 지나면 호감 60 이상일 때만 영입됩니다.
  - 영입되면 계약금을 지급하고 `GuildRoster.AddExisting`을 호출합니다.
- **규칙 기반 대체**
  - 키워드 점수: 가치관 키워드(돈/보상·명예·동료·모험·안전·지식)와 칭찬/무례 단어
  - 특성별 고정 대사 풀
- **완료 기준**
  - LLM 유무와 관계없이 영입과 거절이 모두 가능
  - 대화 중 게임은 계속 진행(비동기)

### P3-4 LLM 파티 결성
- **의존**: P3-2
- **파일**: `Adventurers/PartyService.cs`
- **흐름**
  1. `QuestAcceptedEvent`가 오고, `MaxParty>1`이며 첫 수락자(리더)일 때 시작합니다.
  2. 마을에 대기 중(`TownIdle` 또는 `Deciding`)인 길드원 중 후보를 최대 `MaxParty-1`명 고릅니다. 적합도가 높은 순서입니다.
  3. 리더의 초대 대사는 템플릿으로 만듭니다.
  4. 각 후보에게 LLM 요청을 보냅니다(우선순위 `Party`): `{"accept":"yes|no","say":str}`
     - 후보의 관점으로 판단합니다(성격, 특성, 리더와의 관계, 퀘스트 정보).
  5. 수락하면 `TryAccept`를 호출하고 `TravelState`로 전환합니다. 리더에게 동행 보너스로 이속 버프를 줍니다.
- **규칙 기반 대체**
  - 조건: `RuleBasedDecisionMaker.Score > 0`
  - 확률: 가치관이 "동료"면 0.8, 특성이 "외톨이"면 0.2, 나머지는 0.55
- **완료 기준**: 2인 이상 의뢰에서 파티가 함께 출발하고, 대사 말풍선이 표시됨

## P5 밸런스, 최적화, 빌드

### P5-1 밸런스
- **대상 수치**: `GameBalance`, `DefaultContent`
- **목표**
  1. 첫 레벨업은 1일차 안에
  2. 3일차 첫 웨이브는 초기 길드원 3명과 장비 1등급으로 방어 가능
  3. 무분별하게 사냥하면 5일 이내 멸종 위기 경고가 뜨고, 관리하면 개체 수가 안정
  4. 골드가 계속 부족하지도, 넘치지도 않음
- **알려진 문제**
  - 둥지 2개인 종이 한 번에 멸종 → 둥지 최소 수 보장, 멸종 위기 종 토벌 의뢰 경고
  - 레벨업이 느림
- **방법**
  - `DebugCommands`로 10일 가속 시뮬레이션을 돌리고, 지표(골드/EXP/개체수/레벨)를 CSV로 기록합니다.

### P5-2 성능
- **목표**: 유닛 200과 투사체 100이 있는 상황에서 60FPS
- **점검 대상**
  - `UnitRegistry` 선형 쿼리 → `CrowdSimulation` 공간 해시 쿼리로 교체
  - 안개 전체 갱신 → 변경 영역만 갱신
  - A* 요청 분산(프레임당 상한)
