# 길드 마스터 타이쿤 — 설계 문서 (v1)

원본 기획서를 바탕으로, 질의응답으로 확정한 결정 사항을 반영한 구현 설계입니다.

## 0. 원본 기획서에서 변경/확정된 사항

| 항목 | 원본 기획서 | 확정 |
|---|---|---|
| 엔진 | Unity 2022 LTS | **Unity 6 (6000.0.60f1)**, 2D URP |
| LLM | Ollama/LM Studio + UnityWebRequest | **LLMUnity** (게임 내장 llama.cpp), Qwen2.5 3B급 GGUF, 한국어 |
| JSON | Newtonsoft.Json | **JsonUtility + GBNF 문법 강제** (형식은 문법이 보장, 파싱 실패 시 규칙 기반 대체) |
| 화폐 | 모호 | **골드 + EXP** (아래 경제 참조) |
| 사냥 자원 | 업그레이드 재료 | 업그레이드 + 물약/장비 **제작** + 행상인 **외부 판매** |
| 플레이어 | 모호 | **비전투 아바타** (클릭 이동, 시야 제공, 방문 모험가와 대화) |
| 승패 | 인프라 파괴 시 종료 | **무한 모드**, 마을회관 파괴 시 패배. 생존 일수/길드 규모 기록 |
| 퀘스트 인원 | 명시 없음 | **NPC가 LLM으로 파티 결성** (리더가 동료 섭외 → 동료가 수락/거절) |
| 카메라 | Cinemachine | **자체 컨트롤러** (팬/줌/경계/추적/흔들림) |
| 아트 | 픽셀아트 | 우선 **코드 생성 임시 스프라이트**. `SpriteFactory`만 바꾸면 교체 가능 |

## 1. 코어 루프

```
몬스터 둥지 번식/이동 → 마을 위협도 상승
  → 플레이어: 의뢰 게시판에 퀘스트 등록 (보상 = 골드 + EXP, 권장 인원)
  → NPC(LLM): 성향/상태/위험도로 수락 판단, 필요하면 파티 섭외
  → NPC(FSM): 이동 → 탐색 → 전투 → 전리품 획득 → 귀환
  → 길드에 전리품 판매 (플레이어가 골드 지불) + 퀘스트 보상 수령 (골드+EXP)
  → NPC: 레벨업, 번 골드로 길드 상점에서 물약/장비 구매 (플레이어에게 골드 지불)
  → 플레이어: 재료+골드로 건물 업그레이드 / 물약·장비 제작 / 남는 재료 행상인에 판매
```

## 2. 경제

| 자원 | 획득 | 소비 |
|---|---|---|
| 골드(길드) | NPC의 상점 구매, 행상인 판매, 마을 세금(일일) | 전리품 매입, 퀘스트 골드 보상, 업그레이드, 제작 |
| EXP(길드 풀) | 시간당 자동 수급 (길드홀 레벨에 비례) | 퀘스트 EXP 보상 (등록 시 예치, 취소 시 환불) |
| 재료 | NPC에게 매입 | 업그레이드, 제작, 행상인 판매 |
| 상품(물약/장비) | 제작 (재료+골드) | NPC에게 판매 |
| NPC 골드/EXP | 전리품 판매, 퀘스트 보상 | 상점 구매 / 레벨업 |

퀘스트 보상은 **등록할 때 예치(escrow)**합니다. 그래서 보상을 약속해 놓고 지급하지 못하는 상황이 생기지 않습니다.

## 3. 아키텍처

### 3.1 어셈블리(asmdef) — 의존 방향은 한쪽으로만

```
GuildMaster.Core        (의존 없음)          EventBus, ServiceLocator, GameClock, ObjectPool, SpriteFactory, Random
   ▲
GuildMaster.LLM         (Core, [LLMUnity])   ILLMBackend, LLMService(우선순위 큐/타임아웃), 프롬프트, GBNF, DTO
   ▲
GuildMaster.Gameplay    (Core, LLM)          World, Units, Monsters, Ecosystem, Economy, Quests, Adventurers, Town, Player
   ▲
GuildMaster.UI          (Core, LLM, Gameplay) HUD, 패널, 말풍선, 플로팅 텍스트, 미니맵
GuildMaster.Editor      (전부)                기본 데이터(ScriptableObject) 생성기
GuildMaster.Tests       (전부)                EditMode 테스트 (A*, 경제, 생태계, JSON)
```

- 시스템끼리는 **EventBus**(타입 기반 publish/subscribe)로 느슨하게 연결합니다. 예: `UnitDied` → 생태계 개체수 감소, 퀘스트 진행, 로그, 사운드.
- 전역 서비스는 **ServiceLocator**에 등록합니다. 씬 부트스트랩(`GameBootstrap`)이 초기화 순서를 명시적으로 결정합니다.
- LLMUnity 의존은 `LLMUnityBackend.cs` 한 파일에만 둡니다. asmdef `versionDefines`로 패키지가 있을 때만 컴파일합니다. 패키지나 모델이 없으면 `RuleBasedBackend`로 자동 전환되어 게임은 항상 돌아갑니다.

### 3.2 AI 하이브리드

| 계층 | 담당 | 구현 |
|---|---|---|
| 저수준 (매 프레임) | 이동, 길찾기, 사거리, 전투, 도주, 시야 | C# FSM (`StateMachine<T>`, `IState`) + 그리드 A* |
| 고수준 (수 초~수십 초) | 퀘스트 선택, 파티 섭외/수락, 상점 이용, 영입 대화, NPC 잡담 | `LLMService` → LLMUnity, JSON 응답 |

- NPC의 고수준 판단은 **DecisionState**에서 비동기로 요청합니다. 기다리는 동안 NPC는 마을에서 배회(idle)하므로 게임이 멈추지 않습니다.
- `LLMService`는 **우선순위 큐**로 요청을 한 번에 1개씩 처리합니다. 우선순위는 영입 대화 > 파티 > 퀘스트 판단 > 잡담 순입니다.
  - 같은 NPC의 판단 요청이 쌓이면 이전 요청을 버립니다.
  - 타임아웃이 지나면 규칙 기반 판단으로 대체합니다.
- 응답 검증: GBNF가 형식을 보장합니다. 그 위에서 의미 검증(존재하지 않는 quest_id 등)을 하고, 실패하면 규칙 기반 판단으로 대체합니다.

### 3.3 LLM 스키마 (기획서 3.2 확장)

요청 컨텍스트(프롬프트에 JSON으로 삽입):
```json
{
  "npc_id": "NPC_001", "name": "카엘", "mbti": "ESTP", "values": "돈",
  "traits": ["탐욕스러움", "겁많음"],
  "status": { "hp_percent": 35, "gold": 120, "fatigue": 70, "level": 3 },
  "available_quests": [
    { "quest_id": "Q_101", "target": "고블린 토벌 x5", "reward_gold": 50, "reward_exp": 30, "danger": "Low", "party_size": 1 }
  ]
}
```
응답(문법 강제):
```json
{ "action": "accept_quest|rest|shop|idle", "quest_id": "Q_101", "reason": "...", "say": "말풍선 대사" }
```

## 4. 시스템 명세 (핵심 수치는 `GameBalance` ScriptableObject)

- **시간**: 게임 1시간 = 실시간 10초, 하루 = 24시간(4분). 배속 0/1/2/4.
- **맵**: 128×128 타일을 절차적으로 생성합니다(시드 고정 가능).
  - 중앙에 마을(성벽/건물), 주변에 초원·숲·산·물이 있고, 몬스터 둥지 여러 개를 배치합니다.
  - `GridMap`이 통행 가능 여부와 이동 비용을 관리합니다.
- **길찾기**: 8방향 A*, 이진 힙, 대각선 모서리 통과 금지. 경로 캐시는 쓰지 않습니다(맵이 작음).
- **안개**: 타일당 1px 텍스처 3단계(미탐색/탐색됨/보임), 0.2초마다 갱신합니다. 시야 밖 몬스터는 렌더링하지 않습니다.
- **전투**: `Health`, `CombatStats`(공격/방어/사거리/쿨다운/이속/시야)를 씁니다. 피해 = max(1, 공격 − 방어/2) ± 10%.
- **생태계**:
  - 둥지마다 종/수용량이 있고, 로지스틱 성장으로 번식합니다.
  - 해당 종의 전체 개체수가 0이 되면 멸종하고 스폰이 중단됩니다.
  - 포식 관계: 늑대→슬라임, 오크↔고블린 등.
- **퀘스트 종류**: 토벌(종 × 수), 둥지 소탕, 탐사(구역 안개 해제), 방어(웨이브 중 자동).
- **모험가**:
  - 레벨/스탯, 림월드식 ±특성 1~3개(상충 특성 제외), MBTI, 가치관을 가집니다.
  - 체력/피로/골드/인벤토리를 관리합니다.
- **영입**: 방문자가 광장에 일정 시간 머무는 동안 플레이어 아바타가 다가가 대화합니다. LLM이 호감도와 결정(accept/reject/undecided)을 반환합니다.
- **웨이브**: N일마다 맵 가장자리에서 대규모 침공이 옵니다. 모험가는 방어 모드로 바뀝니다. 마을회관 HP가 0이 되면 게임 오버입니다.
- **건물**: 길드홀(EXP 수급/정원), 대장간(장비 제작 티어), 약방(물약 제작), 훈련소(대기 중 EXP), 성벽/마을회관(HP).

## 5. 개발 순서

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **P1** | Core 프레임워크, 맵 생성, 카메라, A*, 안개, 플레이어 아바타 클릭 이동 | 맵을 둘러보고 클릭 이동 시 안개가 걷힘 |
| **P2** | 유닛/FSM/전투, 몬스터·생태계, 풀링, 경제, 의뢰 게시판, 모험가 사냥→판매→보상 루프(규칙 기반 판단) | LLM 없이 코어 루프 완주 |
| **P3** | LLMUnity 연동, 특성, 영입 대화, LLM 퀘스트 판단/파티 결성/잡담, 말풍선, 웨이브 | LLM 판단으로 루프 동작 + 오프라인 대체 |
| **P4** | 건물 업그레이드/제작/행상인, 정보 패널, 미니맵, 이펙트, 사운드 | 전체 UI/UX |
| **P5** | 밸런싱, LLM 지연/예외 처리, 빌드 | Windows .exe |
