# 의뢰 협상 (Quest Negotiation, P4-25)

> 장시간 아무도 맡지 않은 의뢰를 두고, 길드 마스터가 길드원과 **보상 골드 인상**과 **NPC의 역제안**으로 협상하는 기능.
> 기존 P4-24 "의뢰 설득"을 확장해서 만들었고, 길드원 영입용 설득(RecruitDialog)과는 별개다.

- 구현일: 2026-09-19
- 엔진: Unity 6000.3.24f1
- 상태: 구현 완료, EditMode 테스트 121/121 통과 (신규 15개), 인게임 동작 확인
- 이 문서는 팀원 작업 목록(`TEAM_TASKS.md`)에 없는 항목이다. 동료가 맡은 P4-22, P4-23, P4-13, P4-19, P5-1~P5-6, P4-9, P4-12는 건드리지 않았다.

---

## 1. 무엇을 하는 기능인가

NPC(길드원)는 성격과 가치관, 위험 성향에 따라 의뢰를 수락하거나 거절한다. 그래서 아무도 맡지 않는 의뢰가 생긴다.
그런 의뢰가 **6게임시간** 넘게 방치되면 게시판에서 "협상"이 열린다. 길드 마스터는 마을에 있는 길드원을 골라 이야기하고, 두 가지 수단으로 마음을 돌린다.

1. **보상 골드 인상**: "+10% / +25% / +50%" 버튼으로 보상을 더 얹겠다고 제안한다.
2. **NPC의 역제안**: 마음이 움직였지만 부족한 NPC가 "+NG를 더 주면 맡겠다"고 가격을 부른다. 길드 마스터는 수락하거나 거절한다.

합의되면 인상분이 길드 금고에서 빠져나가 의뢰 보상에 더해지고, NPC는 의뢰를 맡고 출발한다.

### 기존 설득(P4-24)과의 관계

| 구분 | 기존 설득 (P4-24) | 협상 (P4-25) |
|---|---|---|
| 여는 조건 | 의뢰가 6게임시간 미수락 | 동일 (같은 창을 확장) |
| 수단 | 말로 설득 (LLM 또는 규칙 기반 답변) | 말 + **골드 제안 + 역제안** |
| 설득도 | 대화로만 오르내림 | 대화 + 추가 골드만큼 상승 |
| 결과 | 수락/거절 | 수락/거절 + 보상 인상 |

기존 말 설득은 그대로 남아 있다. 협상은 그 위에 얹은 층이다.

## 2. 플레이 흐름

1. 의뢰 게시판(Q)에서 방치된 의뢰 행에 **협상** 버튼이 활성화된다. 열리기 전에는 "협상 N시간 후"로 표시된다.
2. 버튼을 누르면 "의뢰 협상" 창이 열리고, 왼쪽에 마을에 있는 협상 가능 길드원 목록이 나온다. (여유롭게 맡을 수 있는 사람이 위에 온다.)
3. 길드원을 고르면 오른쪽에 설득도 게이지(현재값 / 수락 기준)가 보인다.
4. 아래 협상 줄에서 `+10%`, `+25%`, `+50%` 중 하나를 눌러 보상을 인상 제안한다. 금액은 5G 단위로 반올림된 값이 버튼에 표시된다.
5. NPC가 즉시 답한다.
   - 설득도가 수락 기준에 닿으면 계약을 받아들인다.
   - 기준 근처면 "조금만 더" 식으로 답하고, 필요하면 **역제안 줄**이 나타난다.
   - 기준에서 멀면 "그 정도로는 어렵다"고 답한다.
6. 역제안이 나오면 **역제안 수락**(금액을 얹고 즉시 합의) 또는 **거절**(같은 턴엔 다시 묻지 않음)을 고른다.
7. 협상이 끝나면 로그에 "보상이 협상으로 N G 인상되었습니다"가 남는다.

말로 하는 설득(입력창 + 보내기, 정식으로 부탁하기)은 예전처럼 쓸 수 있고, 두 방법을 섞어도 된다. 대화 턴은 최대 5번이다.

## 3. 규칙 (NegotiationRules)

모든 수식은 `NegotiationRules.cs`에 순수 함수로 들어 있어 EditMode 테스트로 검증한다.

### 3.1 탐욕도 (greed)

```
greed = clamp(GoldGreed × 가치관 보정, 0.5, 2.0)
가치관 보정: 돈 ×1.3 / 명예·모험 ×0.8 / 그 외 ×1.0
```

`GoldGreed`는 NPC 특성에서 온다. 돈을 좋아하는 NPC일수록 골드에 잘 움직인다.

### 3.2 제안 한도

| 항목 | 값 |
|---|---|
| 제안 단위 | 5G |
| 한 협상에서 얹을 수 있는 총액 | 원래 보상의 100% (최소 30G) |
| 실제 상한 | 위 한도 남은 값과 **현재 금고 골드** 중 작은 값 (5G 단위 내림) |

### 3.3 골드가 올리는 설득도

```
설득도 상승 = min(60, floor(40 × greed × 총추가골드 / max(20, 원래보상)))
```

- **총 추가 골드**만으로 계산하므로, 제안을 여러 번 쪼개도 이득이 없다 (`WillingnessFromExtra_DependsOnTheTotal...` 테스트).
- 골드만으로는 최대 +60까지만 오른다. 그 이상은 대화(말 설득)가 필요하다.
- 반대로 수락 기준에 닿는 최소 골드는 `ExtraForWillingness`(역함수)로 구한다. 불가능하면 -1.

### 3.4 역제안 (CounterOffer)

```
부족분 = 수락 기준 + 5 - 현재 설득도
필요 총액 = ExtraForWillingness(이미 얹은 골드의 상승분 + 부족분)
최소 추가액 = max(5, 필요 총액 - 이미 얹은 골드)
요구액 = min( ceil5(최소 추가액 × 1.2), 남은 제안 한도 )
```

다음 경우에는 역제안을 하지 않는다 (0 반환).

- 이미 수락 기준을 넘었을 때
- 체력이 낮아 어떤 의뢰도 못 맡는 상태일 때 (`AcceptAllowed == false`)
- 남은 한도가 5G 미만일 때, 골드만으로는 도달 불가능할 때, 최소 추가액이 남은 한도를 넘을 때

탐욕스러운 NPC는 같은 부족분에 더 적은 골드를 요구하고, 부족분이 작을수록 요구액도 작다.

### 3.5 NPC 대사

`NegotiationLines`가 탐욕도에 따라 세 가지 말투(겸손 ≤0.9 / 보통 / 탐욕 ≥1.2)로 규칙 기반 대사를 고른다. LLM 모델이 없어도 동작하고, 답이 항상 즉시 나온다.

- `OfferReply`: 계약 / "조금만 더" / "어림도 없다"
- `CounterLine`: "{N}G만 더 주시면 맡겠습니다" 형태
- `DeclinedLine`, `DealLine`

### 4.3 PersuasionSession의 협상 상태

| 멤버 | 의미 |
|---|---|
| `BaseRewardGold` | 협상 시작 시점의 보상 (인상 폭의 기준) |
| `Greed` | 이 NPC의 탐욕도 |
| `OfferedGold` | 지금까지 약속한 추가 골드. **합의될 때만** 금고에서 빠진다 |
| `Counter` | NPC가 부른 가격 (0이면 역제안 없음) |
| `MaxOffer`, `CanOffer` | 지금 더 제안할 수 있는 최대액과 가능 여부 |

`Offer(int)`는 동기 처리이고 LLM 호출이 없다. 설득도에 상승분을 더하고 규칙 기반 대사를 낸 뒤 `PersuasionRules.Judge`로 판정한다. 제안도 대화 턴 하나로 세므로 5턴 제한에 포함된다.

### 4.4 지불과 수락 처리 (TryApplyAcceptance)

```
1. NPC가 유효한가 (생존, 미배정, 자리 있음, 체력 기준) → 아니면 Unavailable
2. OfferedGold > 금고 골드 → NoFunds  (의뢰를 맡기기 전에 검사하므로 반쪽 계약이 남지 않는다)
3. QuestBoard.TryAccept(quest, npc)     (기존 수락 경로 그대로, 파티 초대 등도 동일)
4. QuestBoard.TryRaiseReward(quest, OfferedGold) → 금고 차감 + 보상 인상 + 이벤트 발행
5. npc.CurrentQuest = quest, TravelState로 전환
```

보상은 이미 에스크로(예치)된 구조이므로 인상분도 금고에서 즉시 빼서 의뢰에 붙인다. 완료 시 지급액은 기존 `PayGold` 분배를 따라 인상분까지 반영된다.

### 4.5 이벤트, 로그, 기억

- `QuestRewardRaisedEvent { Quest, Gold }`: 보상이 오를 때 발행
- 게임 로그: 협상 성사 "보상이 협상으로 N G 인상되었습니다", 자금 부족 "길드 자금이 부족해 ... 협상이 무산되었습니다"
- NPC 기억: "길드 마스터와 협상해 보상을 N G 더 받기로 하고 '의뢰'를 맡았다" (중요도 2)

## 6. 테스트

`NegotiationTests` (EditMode, 15개 통과)

- 탐욕도 계산과 clamp
- `RaiseCap`, `MaxOffer`, `PercentOffer`
- `WillingnessFromExtra`: 골드와 탐욕도에 대한 증가, 상한, 총액 기준(쪼개기 무이득)
- `ExtraForWillingness`: 역함수의 최소성, 불가능 시 -1
- `CounterOffer`: 없어야 하는 경우, 부족분 해소, 탐욕과 부족분에 따른 요구액 순서, 한도 이하, 이미 얹은 골드 반영
- 대사가 비지 않음, 역제안 대사에 금액 포함
- `QuestBoard.TryRaiseReward`: 금고 차감, 보상과 `PayGold` 증가, 자금 부족 및 종료된 의뢰 거부, 이벤트 발행

전체 EditMode: 121/121 통과 (기존 106개 유지).

## 7. 조정 가능한 값

`NegotiationRules` 상수 (밸런스 조정용)

| 상수 | 기본값 | 의미 |
|---|---|---|
| `Step` | 5 | 제안과 역제안의 골드 단위 |
| `MaxRaiseRatio` | 1.0 | 총 인상 한도 (원래 보상 대비) |
| `MinCapGold` | 30 | 싼 의뢰도 최소 이만큼은 얹을 수 있음 |
| `MaxGain` | 60 | 골드만으로 올릴 수 있는 설득도 상한 |
| `GainPerDoubling` | 40 | 보상을 2배로 올렸을 때 (greed 1) 설득도 상승 |
| `MinBaseGold` | 20 | 아주 싼 보상의 비율 계산 하한 |
| `CounterMargin` | 5 | 역제안이 수락 기준보다 이만큼 위를 노림 |
| `AskPadding` | 1.2 | 필요 최소액에 얹는 흥정 여유 |

창의 `OfferPercents = {10, 25, 50}`는 `PersuadeDialogView.cs`에 있다. 방치 시간은 기존 `PersuasionRules.OpenAfterHours`(6시간)를 그대로 쓴다.

## 8. 알려진 한계와 참고

- 인게임 확인은 방치된 의뢰를 게시판 목록에 직접 추가하고 위험도를 High로 맞춘 상태로 진행했다. 게시판에서 6시간을 기다려 "협상" 버튼이 열리는 흐름은 직접 확인하지 못했다.
- 시험 중 NPC들이 대부분의 의뢰를 곧바로 맡아서, 실제 플레이에서 "방치되는 의뢰"가 얼마나 자주 생기는지는 따로 지켜볼 필요가 있다. 협상 창이 열리는 빈도는 밸런스에 달려 있다.
- LLM 모델(`qwen35-4b-q4km.gguf`)이 없으면 말 설득도 규칙 기반 답변으로 대체된다. 골드 제안과 역제안은 처음부터 규칙 기반이라 영향이 없다.
- 제안한 골드는 합의 순간에만 금고에서 빠진다. 협상이 결렬되면 아무것도 빠지지 않는다. 합의 순간 금고가 모자라면 `NoFunds`로 끝나고 의뢰는 그대로 남는다.
- 같은 의뢰에 대해 NPC마다 별도 세션이 있고, 의뢰가 닫히면 세션이 정리된다. 한 NPC와의 협상 결과(이미 얹은 골드)는 다른 NPC 세션에 이어지지 않는다.

## 9. 후속 아이디어

- 협상 결과를 NPC와의 관계도(RelationshipTests 계열)에 반영
